# WP-032 — Release Engineering and Supply Chain

## Current status

Release engineering is implemented, but the release baseline is **not ready**
and nothing has been published. T196 remains open until every preceding profile
and fuzz acceptance criterion can pass and the complete release check succeeds.

## Implemented

- Manual, read-only GitHub release-candidate workflow for crate/package docs,
  Linux/macOS/Windows CLI binaries, WASM, manifests, checksums, and SBOM.
- Tracked lockfile, RustSec audit, cargo-deny source/license policy, and pinned
  supply-chain tool versions.
- CycloneDX 1.5 JSON generation using cargo-cyclonedx 0.5.9 with reproducible
  `SOURCE_DATE_EPOCH` handling.
- One-job release gate covering build/test/clippy/fmt/diff, MSRV, generated
  family matrix, regeneration, docs, adapters, profile/migration fixtures,
  fuzz regression/baseline, benchmarks, supply chain, package, SBOM, evidence,
  and checksums.
- Failure injection proves the gate rejects a skipped matrix row, dirty
  generated output, audit/license failure, missing evidence/checksums, and an
  adapter smoke failure.
- Generated release support manifests and verified package candidate evidence.

## Remaining mandatory blockers

- WP-017/WP-018 complete executable profile rule packs remain unavailable
  without exact licensed source artifacts and digests.
- WP-029 coverage-guided fuzz baseline needs cargo-fuzz/libFuzzer downloads,
  which the restricted sandbox cannot perform.
- The online RustSec advisory refresh and cargo-cyclonedx execution require
  tools/network not available in this sandbox; CI is configured to run them.
- Therefore the full `scripts/release-check.sh` has deliberately not been
  reported as passing and no release-ready marker exists.
