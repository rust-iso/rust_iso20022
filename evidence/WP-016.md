## Implemented scope

- `ProfileReleaseKey` contains scheme, scheme release, guideline edition,
  inclusive effective range, and ordered lowercase SHA-256 source digests.
- `ProfileScheme` is an extensible validated identifier rather than a public
  exhaustive enum. Bare names/years cannot parse as release keys.
- `ProfileDate` performs bounded calendar validation without raising the MSRV or
  enabling the optional `chrono` dependency.
- `ProfileRegistry` is immutable after construction, orders release history by
  scheme/effective date, rejects duplicates/overlap, and resolves an as-of date
  only to a stored concrete key.
- Every release has an exact generated catalogue support matrix. Unsupported
  versions and unavailable rule packs return typed errors.
- Available dispatch checks that an L3 `RuleSet` scheme/version matches the
  complete release identity. WP-016 ships no market-profile rules or placeholder
  production registry entries; its executable rule exists only in tests.
- `profiles` is opt-in and absent from default features.
- JSON schemas define source-manifest and fixture-index traceability. Synthetic,
  explicitly test-only source/history fixtures prove digest immutability without
  representing CBPR+ or SEPA content.
- Documentation says results cover implemented rules for the identified release
  and do not promise bank acceptance, certification, onboarding, or compliance.
