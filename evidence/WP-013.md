## Red phase

`cargo test -p rust_iso20022_cli --test inspect_serialize --features
json,model-pacs` compiled the pre-existing model slice and then failed all three
tests because `inspect`, `to-json`, and `to-xml` were unregistered usage errors.
The tests already required core equality, human/JSON views, XML→JSON→XML
round-trip, feature-unavailable behavior, and canary redaction.

## Implemented scope

- `inspect` calls bounded core `detect_message` and maps the returned immutable
  schema descriptor. The CLI has no field walker or metadata table.
- `to-json` calls core `parse` and `ParsedMessage::to_json`; its JSON envelope
  embeds a JSON value rather than an escaped document string.
- `to-xml <MESSAGE_ID>` calls new core `parse_json` and
  `ParsedMessage::to_xml`. The generated `parse_json_auto` match is emitted by
  codegen from the same 1,130-message source as `AnyMessage`, so the CLI owns no
  hardcoded message dispatch.
- Serialization requires explicit CLI `json` plus one enabled `model-*` feature
  (the currently tested slice is `model-pacs`). Default builds expose the
  commands but return stable exit 5/`feature_unavailable` before claiming a
  conversion capability.
- Root `json` is a capability alias over the compatibility `serde` feature;
  existing `serde` callers are unchanged.
- All parse/serialization failures map to static safe messages and typed stable
  codes. Raw XML, JSON, parser details, and canary account data are not logged.
- Standalone CLI and root compatibility shim compile the same command and runner
  modules.

## Machine mappings

All envelopes retain `schema_version: 1`, `command`, and `status` from WP-012.

| Command | Success `data` |
|---|---|
| `inspect` | identity, area, family, version, namespace, root, description, generated module, required feature, field count |
| `to-json` | canonical `message_id` and generated JSON `document` value |
| `to-xml` | canonical `message_id` and generated XML `document` string |

Human `inspect` uses labelled lines. Human `to-json` and `to-xml` write only the
converted document to stdout. Unknown/mismatch/deserialization/serialization
failures use exit 3; compile-time capability absence uses exit 5.
