## Harness

The unpublished `rust_iso20022_benchmarks` crate enables only `model-pacs` and
the focused `model-camt-053-001-09` feature. Its six workloads are:

- pacs.008 parse;
- pacs.008 serialize from a pre-parsed generated value;
- pacs.008 detect;
- pacs.008 L2 validation over the generated value;
- camt.053 parse;
- exact catalogue lookup.

Every workload performs a correctness smoke operation before timing. The
harness has no statistical/benchmark dependency and emits JSON lines. This
keeps it usable in the restricted environment and does not imply statistical
confidence from one run.

Memory and allocation are measured separately from latency. Linux/macOS peak
RSS comes from `getrusage`; each workload is a fresh process. A system-allocator
wrapper reports calls and requested/deallocated/live requested bytes. These are
allocator requests, not RSS or heap attribution.

## Build measurement safety

`scripts/measure-build-baseline.sh` uses validated `mktemp` target directories
and removes only those directories on exit. It never cleans a developer target
directory. Cold builds use one job and debug information disabled. The
benchmark cache is separate and reusable so later smoke runs do not repeat the
9-minute optimized generated-model build unnecessarily.
