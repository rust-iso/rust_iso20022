`compare` module did not exist. After the first implementation, the curated
official-schema assertion also correctly failed when it expected a cardinality
change that is not present in any tracked pacs.008 `.08`, `.10`, or `.14` pair.

The CLI parity suite initially returned usage exit 2 for both tests because
`compare` was not registered.

## Implemented scope

- `compare_descriptors` compares only code-generated `MessageDescriptor` field
  graphs. Raw XSD/XML text and instance messages are never compared.
- `compare_versions` resolves exact endpoints through the generated core
  catalogue and returns typed unknown/unrelated-family errors.
- `VersionDiff` pins both message identities and source XSD SHA-256 digests.
- `SchemaChange` supports field added/removed, type changed, cardinality
  changed, and enum value added/removed with explicit before/after values.
- Output ordering is deterministic by logical path, kind, and values.
- No rename is inferred. Distinct schema type paths remain explicit
  remove/add changes.
- `iso20022 compare` serializes the core DTO directly; JSON/core object parity
  and safe diagnostics are tested.
- Formatting-only miniature XSDs have different raw schema hashes but an empty
  semantic diff. The same fixture proves unrelated-family rejection.
