| Contract | Command | Expected failure observed |

The runtime tests freeze identifier/family/version/latest/namespace/root lookup,
numeric version ordering, pointer identity across indices, explicit unknown and
known-unavailable states, and consistency with the legacy `CatalogueEntry`
surface. Generator tests require deleted, added, duplicate, and misdirected
descriptor rows to fail release verification.

## Implementation evidence

- Catalogue rows and all indices are generated from the same 1,130
  `MessageDescriptor` records as the generated model dispatch. There is no
  separately maintained authoritative message list.
- Identifier, family, version, namespace, and root indices are immutable PHF
  tables whose values are ordinals into `metadata::all()`; all lookup paths
  therefore return the same descriptor allocation.
- Numeric version ordering is stable. The pacs.008.001 fixture orders versions
  `08`, `10`, `14`, and `latest` returns `14`.
- Release coverage verification rejects missing, unexpected, duplicate, and
  wrong-module descriptor rows.
- `CoverageState` distinguishes compiled/available messages, schema-known but
  feature-unavailable messages, and unknown identifiers.
- The legacy `CatalogueEntry`, `all`, `from_message_name`, `from_namespace`, and
  `contains` API remains available and is generated from the descriptor set.
- Runtime schema downloads are documented as non-authoritative until reviewed
  into the schema manifest and regenerated.
