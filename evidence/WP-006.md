## Implemented security boundary

- `ParseLimits::DEFAULT` caps input bytes, nesting depth, total events,
  elements, attributes, per-event text, aggregate decoded text, and children
  per collection.
- `BoundedXmlReader` performs streaming well-formedness checks and rejects DTD,
  entity declarations, XInclude, non-UTF-8 declarations, malformed
  namespaces/structure, and invalid Unicode input. Schema-location hints are
  accepted as inert attributes but are never resolved or fetched.
- Public detect, tree, metadata, header, envelope, and generated deserialization
  entry points run the same preflight before scanning or allocating models.
- Typed XML errors contain only category and numeric limits, never input data.

The security tests currently pass 6 bounded-XML cases covering every resource
dimension and public entry point.

## Structured validation

- `ValidationReport` derives validity, error/warning partitions, completeness,
  and deterministic order from one issue collection.
- Issues include code, severity, logical path, message, rule ID, layer, and
  optional profile/version/source metadata.
- `RuleSet` prevents cross-layer mixing and requires explicit matching profile
  releases.
- `RuleRegistry` rejects duplicate IDs and is the single source for execution
  and `explain` lookup.
- `ValidationPipeline` executes in L1/L2/L3 order and records unavailable layers
  without treating them as successful.

The validation contract currently passes 7 tests.

## Privacy behavior

- Default identifier masking retains four prefix and six suffix characters;
  names, addresses, references, remittance, and complete XML are suppressed.
- Core parse/serialization error `Display` and `Debug` output no longer echo
  underlying XML or parser strings.
- Unsafe full values require both the non-default `unsafe-full-logging` feature
  and an explicit `unsafe` runtime acknowledgement. No adapter enables either.

The privacy canary suite currently passes 4 tests.

ICU4X 2.2 packages requiring Rust 1.86. `Cargo.lock` now pins
`idna_adapter 1.2.1` and ICU4X 2.1.x, which declare compatible MSRVs. The
project MSRV was not raised.

## Compatibility correction found by the gates

The first security implementation rejected every `xsi:schemaLocation`
attribute. The representative `pacs.002.001.10` message contract exposed that
as an `UnknownMessage` regression. The boundary was corrected: schema hints are
accepted as inert attributes, while the streaming reader has no schema resolver
or network/file-fetch path. Both the attack suite and the existing generated
message contract pass after the correction.
