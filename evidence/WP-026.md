# WP-026 Local MCP Adapter Evidence

## Status

**Done — T125–T130 complete.**

## Red phase

The contract suite initially exposed three implementation mismatches: the
versioned schema file was absent, test compilation showed that report issue
views are vectors rather than iterators, and normalized comparison parity found
that the adapter serialized absent `before`/`after` values as `null` while the
core contract omits them. The implementation now matches the core object
exactly. A Rust 1.96 Clippy gate also identified a constant assertion in the
existing default-redaction test; it was converted to a compile-time assertion
without weakening the policy.

## Implemented scope

- `rust_iso20022_mcp` is a separate, non-published, stdio-only binary crate. It
  pins official `rmcp` and `rmcp-macros` 3.0.0 with default features disabled.
- The adapter registers exactly seven tools: detect, inspect, validate, message
  lookup, field lookup, version comparison, and validation explanation.
- Every handler delegates to a core detector, generated parser/binding,
  generated catalogue/metadata, schema comparison, or executable rule
  registry. The adapter owns only transport DTO mapping.
- Input/output JSON Schemas are generated from the registered tools and pinned
  as `schemas/tools-v1.json`. A contract test requires object equality.
- The stdio smoke test negotiates MCP `2026-07-28`, lists seven tools, calls
  `detect_message`, verifies structured output, and observes empty stderr.
- JSON-RPC input lines are bounded to the core XML limit plus 1 MiB protocol
  overhead. Core parsing then applies its XML size, structure, and namespace
  limits.
- Tool schemas expose no path, URL, command, shell, or upload parameter. Source
  and manifest audits reject filesystem, network, child-process, HTTP/client,
  authentication, and logging capabilities in the adapter.
- Malformed, oversized, unsupported, incomplete-profile, and unavailable-layer
  errors are static and do not echo source messages or caller-supplied financial
  values.
- L2 generated-message validation is available for installed bindings. L1 and
  L3 return explicit unavailable errors. Profile requests must still be a
  syntactically complete immutable release key; no implicit latest release is
  selected.

## Toolchain and dependency boundary

The core library remains MSRV **Rust 1.85**. `rmcp` 3.0.0 requires Rust 1.88,
so the separate MCP crate declares `rust-version = "1.88"` and is verified on
the installed stable Rust 1.96 toolchain. Its direct runtime dependency set is:

```text
futures 0.3.32
rmcp 3.0.0
rmcp-macros 3.0.0
rust_iso20022 0.1.2 (default features disabled; serde, model-pacs, profiles)
schemars 1.2.2
serde 1.0.228
serde_json 1.0.150
tokio 1.52.3 (io-std, macros, rt-multi-thread only)
tokio-util 0.7.18 (codec only)
```

Feature-tree inspection contains no Reqwest, Hyper, HTTP transport, client,
authentication, filesystem, network, or process feature.
