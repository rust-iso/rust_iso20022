## Red phase

`cargo test -p rust_iso20022_cli --test explain` initially failed to compile
because neither runtime-string registry lookup nor the CLI explanation mapping
existed. The tests already required L2 object parity, generic L3 profile/source
fields, human output, unknown-ID behavior, and canary redaction.

## Implemented scope

- `RuleRegistry::explain_str` performs runtime ID lookup against the same sorted
  executable rules used by `validate`; no second explanation map exists.
- `Rule::field_paths` is an additive method with an empty default, preserving
  compatibility for external rule implementors. Built-in financial and
  cross-field rules report the paths they actually read or constrain.
- `RuleExplanation` is an additive core view that flattens the existing static
  `RuleDescriptor` plus field paths from the executable rule. The public
  `RuleDescriptor` layout was deliberately left unchanged to avoid breaking
  downstream struct literals.
- The CLI `explain` command returns this core view directly. Its JSON includes
  ID, layer, title, reason, source/reference, profile, exact profile version,
  affected messages, and field paths.
- `explain_from_rules` accepts a core rule set, allowing an installed exact
  profile release to use the same mapping. The L3 contract test uses a clearly
  synthetic test rule and does not claim CBPR+ or SEPA rules are installed.
- Unknown rules return exit 5 with `rule_not_found`. Neither JSON nor stderr
  echoes the supplied identifier, protecting identifiers that may contain
  sensitive data.

