# WP-027 WASM Compatibility and Verified Subset Evidence

## Status

**Done — T131–T136 complete.**

## Red phase

The first structured round-trip test failed because it compared JSON text and
therefore treated map-key ordering as semantic. It was corrected to compare
deserialized objects, while still proving XML → generated struct → JSON →
generated struct → XML parity. The unavailable-family test initially selected
an untracked `camt.053.001.08`; changing it to the tracked `.09` release then
proved the intended `model-camt` preflight result.

The first headless-browser attempt also exposed an environment tooling mismatch:
wasm-pack downloaded ChromeDriver 148 while installed Chrome was 153, producing
a driver 404. The final browser gate removes that external coupling: a temporary
loopback HTTP server loads the generated web ES module and `.wasm` in installed
headless Chrome, executes real detection/catalogue calls, and checks the DOM
result. This browser runtime gate passes.

## Implemented scope

- `rust_iso20022_wasm` is a separate, non-published `cdylib`/`rlib` crate with
  no default generated model. Detection and catalogue remain lightweight.
- The explicit `model-pacs` feature enables generated parse, serialization, and
  L2 validation. Every operation delegates to the core `ParsedMessage`,
  generated dispatch, catalogue, or validation binding.
- Structured bindings use serde DTOs plus `serde-wasm-bindgen`; they do not
  hand-build JSON and do not define a second ISO 20022 message model.
- XML is bounded by `ParseLimits::DEFAULT` before generated parsing/validation.
  JSON input is capped at the same byte limit before generated deserialization.
- Errors have stable structured codes. Oversized/malformed input is redacted;
  unavailable L1/profile validation returns `validation_unavailable`; a tracked
  but uncompiled family returns `unsupported_feature` and exact
  `required_feature`.
- The original root package retains all 22 recorded exports. Its structured
  JSON now routes through shared serde compatibility views; native shape tests
  pin camelCase fields and node attribute-object representation.
- CI checks the legacy target, the lightweight structured target, and the
  structured `model-pacs` target. The common Spec Kit gate runs workspace work
  on stable and separately preserves Rust 1.85 for every package except the
  official-SDK-constrained MCP adapter.

Chrome: browser ES module initialization, detection, catalogue provenance
Optimized model-pacs .wasm: 33,284,824 bytes

The size is a measured known limitation of family-granular `model-pacs`, not a
small-bundle claim. The default structured crate excludes generated models.
