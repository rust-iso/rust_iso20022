## Implemented targets

The separate `fuzz/` workspace is excluded from the normal workspace/MSRV
graph and pins:

- nightly `nightly-2026-09-26` (`rustc 1.101.0-nightly 75a75c3e0`);
- cargo-fuzz `0.13.2`;
- libfuzzer-sys `0.4.13`.

Eight independent targets keep failures and resource costs attributable:

| Target | Surface/invariant |
|---|---|
| `xml` | bounded XML preflight plus tree parsing |
| `detect` | structured and compatibility detection agree on success |
| `namespace` | namespace/bare-ID parsing and canonical round-trip |
| `financial` | IBAN/BIC/LEI idempotence plus selected scalar validators |
| `mt_parser` | panic-free parsing and in-range field/block spans |
| `mt103` | successful conversion accounts for every parsed field |
| `mt202` | successful conversion accounts for every parsed field |
| `mt940` | successful conversion accounts for every parsed field |

There are 17 persistent valid/invalid/attack seeds. Stable regression tests
include these files at compile time, so missing corpus files fail the normal
test build. The migration replay validates all three successful conversion
seeds against complete mapping-report accounting.

## Automation

`scripts/run-fuzz-regressions.sh` replays the persistent corpus on stable with
one build job and debug information disabled. `scripts/run-fuzz-baseline.sh`
supports bounded runs and explicit corpus minimization. Defaults are 60 seconds
per target, 5-second per-input timeout, 2 GiB RSS, and 64 KiB maximum input.

`.github/workflows/fuzz.yml` runs weekly and on manual dispatch, pins the
toolchain/tool version, replays regressions before fuzzing, optionally minimizes
the corpus, caps the job at 45 minutes, and uploads logs/crash artifacts for 14
days. Timeout, OOM, crash, panic, or non-zero target exit fails the job.

## Historical local blocker for T176

The local sandbox has the correct installed nightly compiler under the
`nightly` alias but does not have cargo-fuzz or libfuzzer-sys cached. Attempting
to check the fuzz workspace failed while downloading crates.io `config.json`:

```text
failed to get `libfuzzer-sys`
Couldn't connect to server (127.0.0.1 proxy endpoint)
```

The sandbox also prevents rustup from creating the exact dated toolchain alias
in the user toolchain directory. The installed `nightly` reports the same
compiler commit as the pinned date, but no libFuzzer execution was fabricated.

T176 remains open until a network-enabled CI/local runner installs cargo-fuzz
0.13.2, builds all eight targets, runs the declared bounded baseline, and
records per-target executions plus crash/timeout/OOM counts and artifact/corpus
digests. WP-029 must not be described as fuzz-baseline complete before that.
