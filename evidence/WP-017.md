# WP-017 CBPR+ Authoritative Rule Set Evidence

## Status

**Partially documented: T091 is complete; T088–T090 and T092 remain open, so
WP-017 is not Done.**

## Blocking dependency

The repository does not contain an authorized final CBPR+ usage-guideline
edition, its immutable source digest/effective dates, or a recorded decision
that the required derived rule metadata may be implemented and distributed in
this open-source project. Public lifecycle summaries are not a substitute for
the exact authoritative rule source.

## Why this blocks completion

WP-017 may claim only rules tied to an exact release, field path, reference,
positive/negative fixture, and distributable provenance record. Creating
synthetic rules, copying restricted source text, or labelling the existing
profile framework as CBPR+ coverage would violate T088, the profile contract,
and the no-false-completion rule.

## Evidence and remaining work

- `profiles/cbpr_plus/source-manifest.json` is intentionally absent because its
  required source identity, digest, access classification, and distribution
  decision cannot be truthfully populated from repository evidence.
- `profiles/cbpr_plus/source-review.json` records the public SR2026 timeline,
  the independent-implementation boundary, and the GitHub references without
  pretending that it is a production source manifest.
- No CBPR+ supported-message claim, rule descriptor, or fixture is shipped.
- A separate opt-in provisional rule set now validates IBAN, BIC, and currency
  syntax through the shared validation target. It is explicitly versioned
  `provisional`, excluded from the authoritative registry, and does not count
  as CBPR+ message coverage.
- `docs/profiles/cbpr-plus.md` publishes an exact zero-support limitation matrix
  and is the completed output of T091.
- Resume of executable rules requires exact source bytes and authoritative
  rule verification. Then execute T088–T090 and T092.

## GitHub reference survey (2026-09-28)

The following repositories are useful implementation references, but none
closes `R-LEGAL-CBPR` or substitutes for an exact SWIFT source edition:

- [`phoughton/iso20022-cbpr-ur`](https://github.com/phoughton/iso20022-cbpr-ur)
  is MIT-licensed and demonstrates year-scoped rule registries, reusable
  conditional/cross-field combinators, enforced-versus-advisory findings, rule
  discovery, and synthetic min/max fixtures. Its README explicitly says the
  package is AI-generated from usage-guideline spreadsheets and must be checked
  against official SWIFT specifications. It is suitable as a differential-test
  oracle candidate, not an authoritative rule source.
- [`socrates8300/mx20022`](https://github.com/socrates8300/mx20022) is an
  Apache-2.0 Rust workspace with generated models separated from parsing and
  scheme validation. Its public documentation claims CBPR+ validation but does
  not identify an exact CBPR+ source release, source digest, effective range,
  or derived-data distribution decision. Its crate boundaries and feature
  strategy are architectural references only.
- [`GoPlasmatic/MXMessage`](https://github.com/GoPlasmatic/MXMessage) is
  Apache-2.0 and advertises SR2025 message coverage and business validation.
  The public README does not provide the source provenance required by T088,
  so its claims and tests may be used only for independent comparison.
- [`Payment-Components/demo-iso20022`](https://github.com/Payment-Components/demo-iso20022)
  demonstrates CBPR+ validation APIs, but the actual rule implementation is in
  a separate binary/commercial SDK. It provides API ideas, not reusable rules.

No third-party message DTO/model will be imported. Any future rule
implementation must operate over this repository's generated structs, use the
existing WP-016 profile registry, carry this project's own source record, and
be verified independently against an authorized exact release.

This blocker does not prevent non-profile SDK, provisional developer checks,
security, fuzzing, performance,
documentation, or release-engineering preparation. It does prevent a release
baseline from claiming CBPR+ support.
