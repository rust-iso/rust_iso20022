## Implemented scope

- `rust_iso20022_cli` is a separate, unpublished workspace package. It depends
  on the root SDK with no model features and owns only process/input/output DTO
  concerns.
- Core `detect_message(xml, limits)` performs bounded detection and returns a
  schema-derived `DetectedMessage` or typed, value-free `DetectionError`.
- CLI `detect` calls only that core API. It contains no namespace catalogue,
  XML parser, or message-identification implementation.
- Stdin is read through a finite `Read::take`; files are rejected by metadata
  size before reading and are still bounded while read. UTF-8/read failures are
  parse failures without echoing bytes or paths.
- Human success stdout is one canonical message ID. JSON stdout is a versioned
  envelope; machine consumers never parse the human text.
- The historical root-package `iso20022` binary compiles the exact same runner
  source for `detect` and retains its pre-existing catalogue query for other
  arguments. There is no copied detect adapter.
- `ValidationFailure`, `Unavailable`, and `InternalFailure` are reserved now so
  later commands cannot change established numeric meanings.

## Machine envelope and streams

Successful JSON stdout:

```json
{
  "schema_version": 1,
  "command": "detect",
  "status": "success",
  "data": {
    "message_id": "pacs.008.001.08",
    "business_area": "pacs",
    "family": "pacs.008.001",
    "version": "08",
    "namespace": "urn:iso:std:iso:20022:tech:xsd:pacs.008.001.08",
    "root_element": "Document"
  }
}
```

Error JSON stdout uses the same first three fields plus
`"error":{"code":"<stable_code>","message":"<safe_message>"}` and no
`data`. stderr receives only the same safe class-level message; source XML,
account values, filesystem content, and parser diagnostics are never written.
Human success leaves stderr empty.

| Exit | Stable meaning | WP-012 exercised behavior |
|---:|---|---|
| 0 | success | human/JSON, stdin/file |
| 2 | usage/configuration | missing/invalid command shape |
| 3 | parse/detection/input failure | unknown, mismatch, limit, read/UTF-8 |
| 4 | validation failure | reserved and enum-pinned for WP-014 |
| 5 | requested capability unavailable | reserved and enum-pinned for WP-014 |
| 10 | internal failure | serialization/internal fallback, enum-pinned |
