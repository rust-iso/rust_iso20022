# MT940 to camt.053

The first MT940 conversion release returns the canonical generated
`camt.053.001.09::Document`. The parsed MT syntax tree and mapping report are
transient conversion evidence, not another ISO 20022 message model.

## Covered tags

| MT940 tag | camt.053 projection | Classification |
|---|---|---|
| `20` | group-header message ID | Exact |
| `25` | account ID (`IBAN` or bounded `Othr`) | Exact/Derived |
| `28C` | statement ID and electronic sequence | Derived |
| `60F`, `60M` | opening balance (`OPBD`) | Ambiguous |
| `61` | repeated report entry | Lossy |
| `86` | preceding entry additional information | Ambiguous |
| `62F`, `62M` | closing balance (`CLBD`) | Ambiguous |
| `64` | closing available balance (`CLAV`) | Ambiguous |
| `65` | forward available balance (`FWAV`) | Ambiguous |

Every parsed occurrence receives one mapping classification. Unknown tags are
`Unsupported`, warned, and included in `unmapped_fields`; they are never
silently discarded.

MT dates contain two-digit years. This release uses an explicit `20YY` policy
and marks affected balance mappings `Ambiguous`. A `:61:` entry inherits the
statement currency, retains amount, debit/credit direction, value date,
transaction code and bank reference, and is marked `Lossy` because MT-specific
substructure has no complete one-to-one projection. `:86:` is associated only
with the immediately preceding `:61:` and remains an explicit review item.

The converter validates calendar dates, currencies, decimal precision, IBANs
when present, generic account bounds, and generated XML round-trips. It does
not claim lossless conversion, bank acceptance, certification, onboarding,
regulatory compliance, or legal compliance.
